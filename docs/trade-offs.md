# Trade-offs

What each decision buys, what it costs today, and the next step if the limit is hit. Every entry corresponds to code that exists; ADR numbers point to the reasoning.

| Decision | Benefit | Cost / limit | Next step |
| --- | --- | --- | --- |
| `skip`/`limit` pagination with exact `total` (ADR 0008) | Numbered pages, jump-to-page, exact counts | `skip` and `countDocuments` cost grow with depth and match count; concurrent inserts or deletes can shift rows between pages | Keyset pagination on `(createdAt, _id)` (indexes already end in it); drop or cache exact totals |
| Dashboard cache in process memory, 60 s TTL, cleared on write (ADR 0007) | Repeat loads cost no queries; fresh after the user's own write | Per instance: other instances stay stale up to 60 s; writes outside the API only show after TTL; empty after restart | Redis cache with shared invalidation, or maintained counters |
| Login rate limit in memory (20 / 15 min / IP) | No infrastructure; slows credential stuffing | Counters are per instance and reset on restart, so the effective limit is N times higher with N instances; per-IP only, no per-account lockout; no limiter on other routes | Shared store (Redis) for `express-rate-limit`; add a general limiter and per-account backoff |
| JWT cookie, no refresh token, no server-side revocation (ADR 0003) | Stateless API, no session store, simple horizontal scaling | Fixed 8 h session (configurable), no sliding renewal: users are signed out mid-work; logout only clears the browser cookie, a stolen token stays valid until expiry; role changes need a new login | Short-lived access token plus rotating refresh token, or a session store / token version on the user |
| Prefix-only search on `searchTokens` (ADR 0001) | Partial-word, index-backed, cheap | No substring, typo tolerance or ranking; stale tokens if a write bypasses `save()`; max 5 terms; more storage and one more index per collection | Atlas Search or another engine behind `utils/search.ts`; backfill script when searchable fields change |
| `sort=patients` via `$lookup` + `$count` per doctor (ADR 0002) | No stored counter to keep in sync; always accurate | Computes a count for every matching doctor before paging, cost grows with doctors | Denormalised `patientCount` on Doctor, updated on patient create, delete and reassign |
| Non-transactional doctor delete (ADR 0006) | Works on a standalone MongoDB; safe failure mode (unassigned patients, retry completes) | Two writes are not atomic; a patient assigned between them can end up with a dangling doctor id; `populate` then returns `null` | Wrap in a session transaction on a replica set |
| Two roles, role stored in the JWT (ADR 0005) | Simple, safe by default for new write routes | No finer permissions; role change needs re-login; no user-management API (users come from the seed script) | Re-read role per request or version the token; user admin endpoints |
| Unversioned `/api` (ADR 0009) | Minimal surface, one deployable contract | Client and API must ship together; removals break old clients during a rolling deploy | Add `/api/v2` alongside when a second consumer appears |
| Same-origin proxy through Next.js (ADR 0003) | First-party cookie, `SameSite=Lax`, no preflights | Extra hop for each call; Next.js must reach the API (`API_URL`); `trust proxy` hard-coded to 1 hop | Terminate both behind one reverse proxy; make trust-proxy configurable |
| Coarse client invalidation (ADR 0004) | Counts stay consistent across lists, headers and dashboard | One write refetches every mounted doctor, patient and dashboard query | Targeted `setQueryData` or key-scoped invalidation |
| Dashboard aggregations scan collections | Always correct, no counters to maintain | `patientsByCondition`, `doctorsBySpecialization` and the per-day groupings read the collections (day groupings use the `createdAt` index range); cost grows with data | Cache (already present) then counters/materialised view |
| `autoIndex` off in production | No index builds on boot | Indexes must be created in a deploy step or they will not exist | Migration or deploy script that calls `syncIndexes` |
| `/api/health` pings the database | Load balancers drop a node that lost MongoDB | A database blip marks every instance unready simultaneously | Separate liveness and readiness endpoints |
